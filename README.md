# GTD 月曆

純 HTML／CSS／JS 的個人待辦月曆，不需要安裝或啟動任何伺服器。用 Chrome 或 Edge 直接開 `index.html`。

## 線上 DEMO

部署在 GitHub Pages：<https://yuandata.github.io/GTDCalendar/>。

- 網址在 `*.github.io`（或帶 `?demo=1`）時自動進入 DEMO 模式：讀 `demo-data.js` 的範例，日期以「與今天相差幾天」表示，所以範例永遠落在目前這幾週。
- DEMO 不連結、不寫任何檔案，也沒有加密開關；新增、拖曳、改色、復原都能試，重新整理即還原，要保存請按「下載備份」。
- 本機用 `file://` 開 `index.html` 時行為不變。本機預覽 DEMO：在專案資料夾執行 `python -m http.server 8080`，開 `http://localhost:8080/?demo=1`。
- 個人資料檔 `gtd-data.js` 與密鑰 `naisho.js` 在 `.gitignore`，不會上傳。

## 使用

1. 開啟 `index.html`。
2. 第一次使用時，頂端會出現提示條：
   - 已有 `gtd-data.js`：按「選擇現有檔」。
   - 還沒有：按「建立新檔」，存到與 `index.html` 同一個資料夾，檔名 `gtd-data.js`。
3. 之後每次改動都會直接寫回該檔（不會跳下載或另存對話框）。重開瀏覽器後若出現「允許」按鈕，按一下即可。

資料檔預設是 `index.html` 同資料夾的 `gtd-data.js`（已列入 `.gitignore`，不進版控），位置寫在 `app.js` 的 `DEFAULT_DATA`。
測試時可用 `index.html?data=file:///路徑/其他檔.js` 改讀別的檔案。

## 資料格式

格式範例見 `data.sample.js`。檔案是一段 JS（`window.GTD_DATA = {...}`），內容是 JSON：

| 欄位 | 說明 |
|---|---|
| `date` | 起始日 `YYYY-MM-DD`（欄位排第一個） |
| `done` | 是否完成 |
| `text` | 事項文字 |
| `end` | 結束日，有才是跨日事項，必須晚於 `date` |
| `color` | 色名，可省略。`mint teal sky lavender yellow amber coral pink gray brown dgray`。已過期或已勾選的事項會自動顯示成較淺的顏色 |
| `strikeout` | 只有 `true` 才會有這個欄位（排在 `color` 之後）；有的話文字畫刪除線。在「編輯事項」勾選「刪除線」設定 |
| `weeks`（頂層） | 顯示週數 3~8，預設 7 |

- `items` 依 `date` 倒序，最新的在最上面；同一天內由上而下就是畫面順序。
- 每次存檔，程式會把檔案重新整理成固定排版（FORMATTER）。手改後重新整理頁面即可看到。

## 操作

- 新增：每格日期列中間的「＋」，Enter 送出並可連續輸入，Esc 結束。
- 編輯文字：雙擊事項。刪除：滑過事項按 `×`。勾選：前面的方框。
- 顏色：事項右側的圓點，三列色盤（含「無」）。新增的事項依序套用薄荷、青、天藍、薰衣草。
- 跨日：事項右側的「⋯」設定起始日與結束日。跨日事項顯示為橫條，可整條拖曳搬移。
- 拖曳：同一天內排序，或拖到其他天。
- 復原／重做：畫面下方工具列左側的 `↶` `↷`，滑過按鈕可看到要復原的動作。只涵蓋事項資料（新增、刪除、改字、勾選、改色、搬移、編輯面板），不含週數滑桿和翻頁。一個動作算一步，最多 100 步，只存在記憶體，重新整理就清空；復原／重做後會同步存檔。
- 導覽：畫面下方的功能列 `«月 ‹週 回到今天 週› 月»`（回到今天置中）。移動位置不會被記住，重新整理回到本週。

## 加密（防君子不防小人）

工具列左側的「加密」開關，會把每筆事項的 `text` 加密後再存進資料檔；`date`、`done`、`end`、`color`、`strikeout` 仍是明文。

- **開啟**：要先連結好資料檔。輸入兩次密鑰（可以很短，至少 1 個字）。程式用 SHA-256 迭代展開成 64 字元的長 key，寫進 `naisho.js` 的 `var NAISHO`，再把資料檔的 `text` 改存成 `enc:…` 開頭的密文。第一次會跳出選檔視窗，請選專案資料夾裡的 `naisho.js`（沒有就建立）。
- **之後每次開頁**：要先輸入密鑰，和 `NAISHO` 比對相符才解密。輸入錯誤或取消，事項文字顯示 🔒，整個月曆唯讀，也不會存檔；可從頂端橫幅再輸入。
- **關閉**：要再輸入一次密鑰確認，通過後資料檔的 `text` 還原成明文，`NAISHO` 清成空字串。
- 加密開啟期間，畫面與復原歷史是明文，只有存檔時加密；「下載備份」輸出的內容和資料檔一致（加密時是密文）。
- 加密關閉時，`enc:` 開頭保留給密文使用，不能當作事項文字（開啟加密後則不受限）。
- `naisho.js` 遺失但資料檔有密文：輸入密鑰後會進入「唯讀預覽」，確認解出的內容正確，再按「確認並重建」才寫回 `naisho.js`。
- 實作在 `cipher.js`（純 JS 的 SHA-256 與金鑰流 XOR）。`naisho.js` 已列入 `.gitignore`。

**已知限制**
- 密鑰展開後的 key 就存在 `naisho.js`；同時拿到該檔和資料檔的人就能解開，所以只擋得住隨手打開資料檔的人。
- 沒有檢查碼：解密本身無法偵測密鑰錯誤，驗證靠和 `NAISHO` 比對。
- 沒有 salt：相同文字、相同密鑰會得到相同密文。
- 忘記密鑰就無法還原事項文字。
